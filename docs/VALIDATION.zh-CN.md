## 契约、存储与协议替身

| 场景 | 实际验证 |
|---|---|
| 外部 service | 独立消费者只依赖公开 API；第三方只读 service 无须实现上传或修改核心枚举 |
| 共享预算 | 超额操作返回 ResourceBusy；丢弃运行 future 释放预算；块与并发配置拒绝越界 |
| 文件 checkpoint | 0600 文件、独占锁、子进程写入排斥、损坏 / 超大记录拒绝且保留；超大保存不覆盖旧记录 |
| 恢复绑定 | 公共 / 私有版本不兼容、源变化、不同实例和错误确认回执均拒绝，保留记录 |
| 服务端偏移 | 对账领先本机持久偏移、服务端偏移回退均按服务端结果恢复，不按本地发送量确认 |
| 上传失败窗口 | HTTP 替身断开完成响应后查询原对象；完成后回执保存失败，后续运行重新查询并补存回执 |
| 暂停与重启 | 暂停后续块；读取期间收到停止信号不再发块；新子进程加载真实文件 checkpoint 后续传 |
| 协议 | 空文件、跨块、异常 Range、401 单次刷新 / 二次拒绝通知、429 / 403 限流及 5xx 有界重试 |
| 会话过期 | 默认 SessionExpired 且保留；显式重建复用对象 ID；每次运行最多重建两次 |
| 目录与重名 | 不复用无归属目录；拒绝文件重名；显式操作后缀；目录创建响应丢失后按原目录 ID 对账 |
| 端点与脱敏 | 生产 session URL 限 Google HTTPS 固定路径；测试端点仅 cfg(test)；token / 私有状态 Debug 脱敏 |

HTTP 替身使用可控本机 TCP 服务，包含实际断连接；不能替代 Google 服务端行为验收。
进程测试验证重启和锁释放，不模拟文件系统断电、磁盘固件缓存或所有 fsync 失败窗口。

未控制地理区域、网络出口、缓存或服务端负载。`/usr/bin/time -l` 测量直接运行的
探针进程，含源身份哈希、上传、对账和验收下载，不含 cargo 编译。

| 样本 | 总耗时 | 峰值 RSS | macOS peak memory footprint |
|---|---:|---:|---:|
| 17 MiB 完成结果丢失注入与校验 | 13.28 s | 26,460,160 bytes | 15,810,992 bytes |
| 17 MiB 退出后恢复与校验 | 7.38 s | 26,279,936 bytes | 15,712,688 bytes |
| 256 MiB 新上传与校验 | 73.73 s | 26,001,408 bytes | 14,909,848 bytes |

256 MiB 样本按整个探针耗时折算约 3.47 MiB/s，**不是纯上传吞吐或固定速率承诺**。
单路持有的上传块上界 8 MiB，共享调度预算上界 16 MiB；由所有权与预算门禁验证，
未用分配器追踪测量数据缓冲峰值，也未做真机双路峰值测量。进程 RSS 包含 TLS、
执行器、校验与 IO 复制等额外开销，不等于上传块预算。大文件样本采集后进一步将
Tokio 文件 IO 内部复制缓冲限制为 256 KiB；该收紧经两平台测试，但资源样本未重采。

## 完整架构审查与公开 API 重构（2026-10-02）

本轮范围覆盖 core 公开契约与两个方向的状态机、fs / GDrive service、CLI
宿主、独立消费者和设计文档。审查确认并修正以下问题：

| 问题 | 修改与验证 |
|---|---|
| 上传与下载互相引用公共类型 | 共有生命周期归 transfer，摘要证据归 content；消费者与外部替身仅通过公开接口接入 |
| 引擎调用重复组装存储与控制参数 | TransferEngine 持有存储与共享预算；UploadOptions / DownloadOptions 提供默认构造；普通调用不要求回调或停止信号 |
| 确认回执逻辑重复且方向不一致 | 共用 confirm，校验准确回执后清理；记录缺失时幂等成功；保留业务先记账的要求 |
| 核心混入原生路径规则 | 意图只校验不透明引用边界；GDrive 与 fs 各自解释路径，fs 准备与恢复发布均要求稳定绝对路径 |
| 预算与 IO 块上限不一致 | 端口显式声明上限 / 对齐；32 MiB 预算经 GDrive 与文件源协商为 8 MiB，9 MiB 上传按两块完成；对齐不足在远端准备前拒绝 |
| 上传错误声明摘要验证 | Drive appProperties 为客户端声明；上传回执声明 Length，下载真实校验摘要后声明 Digest；服务端提供非法 MD5 时拒绝，不静默降级 |
| status 对损坏账本直接计算 | DownloadFlow 共用账本校验；反向区间等异常报告为不可读条目，保留原文件，避免减法下溢与求和溢出 |
| 完成下载对账窗口缺少源版本复核 | 本地完成对账后再次查询远端身份；替身在该窗口改变版本，返回 SourceChanged 并保留回执记录 |
| CLI 终端判定和认证失败处理不一致 | 选择器与面板共用三流 TTY 判定；两种方向认证失败均结束队列并保留失败退出语义 |

本机 macOS / arm64 执行并通过：fmt、workspace all-targets check、全特性
Clippy `-D warnings`、workspace tests 和 rustdoc `-D warnings`。常规测试
**123 项**，另有 **1 项文档编译测试**；3 个标记为辅助入口的测试由父测试的
子进程实际执行。未在本轮运行 Linux 或远端 CI，未测量性能改进。

真实 Drive 验收使用已有本机授权和专用新目录 `architecture-review-<随机后缀>`，
源文件为新生成的 17 MiB 内容；没有改动用户原有云端文件。私有日志与 summary
保存在仓库外 `architecture-review-20261002/run-*/`，凭证与私有驱动状态不入库。

| 实际场景 | 结果 |
|---|---|
| 首块持久化后 Ctrl-C | 退出 130，恢复记录保留 |
| 重跑同一上传命令 | 续传完成，退出 0 |
| 再次上传 | 返回同一远端对象，退出 0 |
| 列出测试目录 | 文件可见，退出 0 |
| 下载与校验 | 服务端 MD5 验证通过，本地与源 SHA-256 一致，退出 0 |
| 重复下载 | 原回执与目标复用；最终构建再执行一次，数据读取为 0，退出 0 |
| 验证证据 | 上传 Length，下载 Digest；不把客户端属性作为服务器内容校验结果 |
| status | 本轮两条 v2 记录均为 completed；本机 13 条旧 v1 记录被保留并报告，退出 1 |

兼容性影响：移除 UploadEngine / DownloadEngine 与 RunOptions，改用共享引擎
及 UploadOptions / DownloadOptions；共有类型迁至 transfer / content；IO 端口
需声明块上限。同步迁移了全部仓库消费者、测试和文档。未发布的 v1 平铺
checkpoint 不再转换加载；旧记录没有删除或归档。现有 v2 信封结构保留，
驱动私有版本仍独立校验。工作区改动尚未提交、推送或发布。


## 连续 TUI 与 status 面板验收（2026-10-02）

环境：macOS / arm64，本机 Google Drive `personal` 登录账户与默认盘；
使用当前编译的 `wb`、Python PTY 和真实 Drive，未改账户或默认盘配置。

| 场景 | 验收结果 |
|---|---|
| `status` 列表、详情、刷新、读取问题、退出 | 同一全屏会话；旧格式记录诊断使退出码为 1 |
| 本地目录进入 / 返回 / 取消 | 同一全屏会话；取消返回 130 |
| 云端多选 → 下载面板 → 详情 → 退出 | 同一全屏会话；完成返回 0 |
| 本地多选 → 上传面板 → 退出 | 同一全屏会话；完成返回 0，重新下载测试文本后字节一致 |
| 本地目录补全 → 云端多选 → 下载面板 | 三个页面共用会话；完成返回 0 |
| 下载面板连续两次 Ctrl-C | 返回 130，恢复终端 |

每个场景的 PTY 输出均精确包含一次 `EnterAlternateScreen`（CSI ?1049h）
与一次 `LeaveAlternateScreen`（CSI ?1049l），步骤间不出现退出全屏序列；
由仍持有终端的父进程比较调用前后的 termios，六个场景都完整恢复。
17 MiB 下载文件与源文件 SHA-256 一致；测试文本上传后重新下载，内容一致。

非终端 `status` 与 `status --no-tui` 的标准输出一致；`--json status` 仍为
JSON 数组。三种输出没有 ANSI 全屏控制符，旧格式记录诊断均保留非零退出码。
没有读取或渲染 checkpoint 的驱动私有状态，没有删除旧记录。

验证证据保存在本机私有目录：
`~/Library/Application Support/waybill/ui-review-20261002/`，包含六份 ANSI
记录、`summary.json`、上传文本和下载样本。全屏序列检查证明步骤不退出全屏；
尚未在 Linux 或远端 CI 执行本轮修改，不等于所有终端环境的视觉验收。

workspace fmt、all-targets check、全特性 Clippy、测试与严格 rustdoc 全部通过。
本轮为 126 项常规测试及 1 项文档编译测试；另 3 个辅助入口由父测试通过子进程执行。
